# Printer Compatibility

This document records the printer support boundary for `flutter_report_suite`.

It intentionally separates **implemented software capability**, **automated test coverage**, **emulator/simulator validation**, and **physical hardware verification**. A passing renderer or adapter test is not evidence that a particular printer model has been physically validated.

## Status legend

| Status | Meaning |
| --- | --- |
| ✅ Implemented | The software path exists in the repository. |
| ✅ Automated | Automated tests cover the relevant software behavior. |
| ✅ Emulator/Simulator | The applicable app/package path has been exercised without physical printer hardware. |
| NEEDS PHYSICAL VERIFICATION | No real-device evidence is recorded for that printer model. |
| N/A | The category does not apply to the integration path. |

## Implemented capabilities

### PDF / system printing

`report_engine` provides PDF rendering and a system-printing facade using the `printing` package. The software supports:

- Thermal 80mm PDF output
- Thermal 58mm PDF output
- A4 paged documents
- Thai PDF text with bundled Noto Sans Thai fonts
- system-printer listing where supported by the host platform

System printing support means the application can use printers exposed by the operating system. It does **not** mean every OS-visible printer model has been physically verified with this project.

### ESC/POS rendering

Core ESC/POS support includes:

- template-to-ESC/POS rendering
- TIS-620 byte encoding
- CP874 byte encoding and extensions
- explicit printer code-table configuration
- rasterized Thai fallback
- quick-receipt 8/2/2 item/quantity/price layout
- QR/barcode rendering paths
- transport-independent output

Code-table numbers are printer-specific. A configuration that works on one ESC/POS-compatible printer must not be assumed to work on another clone/model without verification.

### Discovery

`PrinterDiscoveryService` composes discovery sources and provides deterministic domain-safe `UnifiedPrinter` results.

Built-in sources currently include:

- system printers through `printing`
- Bluetooth Low Energy through `flutter_blue_plus`

Important boundary:

> `flutter_blue_plus` is BLE-only. Bluetooth Classic thermal printers need a separate transport/discovery adapter.

The core connection-type model also has `usb` and `network` values so future sources can represent them, but those enum values alone do not mean built-in USB or raw TCP ESC/POS discovery/transport exists.

### Sunmi

Sunmi support is isolated in `packages/report_engine_sunmi` because its plugin dependency is Android-specific.

The adapter supports:

- embedded-printer discovery
- ESC/POS byte transport through the Sunmi service
- printer-service rebind
- optional cutter capability
- optional cash-drawer capability

Cutter and cash-drawer capability are disabled by default. A host must provide a verified `SunmiHardwareProfile` before those interfaces are exposed.

## Automated coverage

Software tests cover the following compatibility-relevant invariants:

- TIS-620 and CP874 conversion
- mixed Thai/English content
- Thai numerals and CP874 extensions
- raster fallback with bundled Thai font assets
- ESC/POS renderer output
- fixed/measured quick-receipt column layout
- transport/service ordering
- fail-before-send behavior for unsupported cut requests
- unified discovery deduplication and exception isolation
- Sunmi capability profile behavior
- PDF Thermal 80mm geometry
- PDF Thermal 58mm geometry
- A4 page geometry
- A4 invoice pagination with more than 25 rows
- Thai A4 invoice rendering

PDF regression tests deliberately validate stable structural properties rather than raw PDF byte equality. Generated PDFs contain values such as timestamps/metadata that can change while the rendered document remains semantically correct.

## Physical verification protocol

When a real printer is available, record at minimum:

1. printer manufacturer and exact model
2. connection type: system / BLE / Bluetooth Classic / USB / TCP network / embedded
3. firmware version if available
4. paper width
5. selected Thai encoding strategy
6. selected ESC/POS code-table number when using TIS-620/CP874
7. Thai sample results for `กุ้ง`, `น้ำ`, `ยอดรวม`, mixed Thai/English, and Thai numerals
8. item/quantity/price alignment result
9. cutter result when applicable
10. cash-drawer result when applicable
11. host OS/device and Flutter app build used
12. date and evidence reference

Only after this evidence exists should a model move from `NEEDS PHYSICAL VERIFICATION` to a physically tested status.

## Known compatibility gaps

The following are intentionally not claimed as built-in, production-verified paths yet:

- Bluetooth Classic ESC/POS transport/discovery
- generic raw USB ESC/POS transport
- generic TCP/network ESC/POS transport
- model-specific XP-80/XP-58 code-table defaults
- model-specific Epson TM-T88V raw ESC/POS adapter
- unconditional Sunmi cutter support
- unconditional Sunmi cash-drawer support

These gaps do not prevent host applications from supplying additional `EscPosTransport` or `PrinterDiscoverySource` implementations.
